# 01 · 功能清单

> 项目具备的全部功能模块与子功能。MVP = 第一版必须具备；进阶 = 后续迭代。
> 标注仅为排期，不代表"可省略"——最终都要生产级实现。

## 1. 账号与认证

| 子功能 | 说明 | 阶段 |
|---|---|---|
| 邮箱注册 | 邮箱 + 密码注册，发送验证邮件 | MVP |
| 邮箱验证 | 点击验证链接激活账号 | MVP |
| 登录 | 邮箱 + 密码，签发 JWT access/refresh | MVP |
| 登出 | 撤销 refresh token | MVP |
| 密码重置 | 邮箱触发重置链接 | MVP |
| 会话管理 | refresh token 轮换，旧 token 失效 | MVP |
| 第三方登录 | GitHub/Google OAuth | 进阶 |

## 2. LLM 配置（用户自带 Key）

| 子功能 | 说明 | 阶段 |
|---|---|---|
| provider 选择 | Anthropic / OpenAI / 兼容 OpenAI 的第三方 | MVP |
| apikey 加密存储 | 服务端加密落库，前端只存掩码 | MVP |
| 模型选择 | 按 provider 列可选模型 | MVP |
| 连通性测试 | 保存前发一次最小请求验证 | MVP |
| 多配置管理 | 一个用户可存多组配置，指定默认 | 进阶 |
| 配额提示 | 保存时提示该 key 的预算配额 | 进阶 |

> 系统不绑死任何 provider；用户未配置时引导其去 setting 上传。

## 3. 游戏生成（对话式）

| 子功能 | 说明 | 阶段 |
|---|---|---|
| 设计会话 | 多轮对话描述游戏需求 | MVP |
| 实时进度 | 生成过程流式推送（策划→美术→代码→质检） | MVP |
| 中断/恢复 | 长任务可暂停、续跑 | MVP |
| 设计稿确认 | 关键节点 HITL，用户确认策划稿再继续 | MVP |
| 迭代修改 | 对已生成游戏提修改意见，增量改 | MVP |
| 版本快照 | 每次生成/迭代存版本，可回看 | MVP |
| 预览试玩 | 生成后直接在页面试玩 | MVP |
| 草稿管理 | 未发布游戏列表、删除、重命名 | MVP |
| 模板/起点 | 选起点模板加速（非玩法约束） | 进阶 |
| 多人协作 | 多人共同设计同一款 | 进阶 |

> "不在业务代码中加硬编码游戏逻辑约束"——玩法完全由 Agent 生成，系统只提供生成能力。

## 4. 游戏运行与托管

| 子功能 | 说明 | 阶段 |
|---|---|---|
| 静态产物托管 | 生成产物（HTML/JS/CSS/资源）落存储 | MVP |
| slug 路由 | 每款游戏分配 slug，`/play/{slug}` 可玩 | MVP |
| 版本管理 | 发布版本与历史版本区分 | MVP |
| 试玩页 | 独立试玩页，嵌入产物 | MVP |
| 资源隔离 | 不同游戏产物命名空间隔离 | MVP |
| 缓存策略 | 静态资源 CDN/缓存头 | 进阶 |
| 访问统计 | 每款游戏 PV/UV | 进阶 |

## 5. 发布与审批

| 子功能 | 说明 | 阶段 |
|---|---|---|
| 提交发布 | 创建者把草稿提交发布审核 | MVP |
| 管理员审批 | 审批通过/驳回（驳回带理由） | MVP |
| 上架 | 通过后对所有人可见可玩 | MVP |
| 下架 | 管理员下架，已下架不可访问 | MVP |
| 重新发布 | 迭代后重新提交发布 | MVP |
| 审批队列 | 管理员看待审列表 | MVP |
| 发布备注 | 创建者写发布说明 | 进阶 |
| 定时上下架 | 按时间自动上下架 | 进阶 |

## 6. 可见性与权限

| 子功能 | 说明 | 阶段 |
|---|---|---|
| 草稿私有 | 未发布游戏仅创建者可见，管理员不可见 | MVP |
| 已发布公开 | 审批通过后所有人可访问 | MVP |
| 角色模型 | 普通用户 / 管理员 | MVP |
| 管理员管理 | 管理员可上下架、管理用户、看用量 | MVP |
| 创建者权限 | 仅创建者可编辑/删除自己的草稿 | MVP |

## 7. 多租户与用量计量

| 子功能 | 说明 | 阶段 |
|---|---|---|
| 每用户 token 计量 | 取 LLM 响应 usage，Redis 累计 | MVP |
| 系统总量 | 跨用户汇总 | MVP |
| 配额限制 | 每用户日/月 token 上限 | MVP |
| 速率限制 | 每用户调用频率限制 | MVP |
| 用量看板 | 用户看自己的用量 | MVP |
| 用量明细 | 按会话/游戏维度拆分 | 进阶 |
| 计费视图 | 估算成本（按 provider 公开价） | 进阶 |

> 计费走用户自带 key，系统不经手钱；统计的是真实 token 消耗与调用次数。
